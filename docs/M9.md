# M9 — Filesystem & Resource I/O

**Goal:** read files from `sdmc:/3ds/PaperBoat3DS/` and look up named
resources with defined alignment and lifetime. Extraction of Nintendo ROMs
stays on the host (M7). This milestone does not run `boot_main`.

## Paths

Canonical root: `sdmc:/3ds/PaperBoat3DS/`

| Logical path | Role |
|---|---|
| `paperboat.o2r` | Port assets (desktop `GeneratePortO2R`) |
| `pm64.o2r` | Game archive (Torch on PC) |

`pb_fs_join` refuses `..`, absolute paths, and drive prefixes. Host tests
remap the logical root with `pb_fs_host_set_root`.

## Lookup

`ResourceGetDataByName` / `pb_fs_lookup`:

1. In-memory register (`pb_fs_register`, 16-byte aligned copy).
2. STORE (method 0) entries inside the two `.o2r` ZIP archives.
3. Otherwise NULL.

Deflate/MPQ payloads are not inflated here. Pointers stay valid until
`pb_fs_shutdown`. Per-blob cap is 512 KiB (Old 3DS). `pb_fs_init` probes
whether the archives exist; missing files are normal until the owner copies
them onto SD.

`source/platform.c` is still the only `3ds.h` owner. libctru mounts `sdmc:`
for stdio; `source/fs.c` uses `fopen` on logical `sdmc:/` paths.

## Host contract

```sh
sh tools/test_m9.sh
```

The contract writes a **synthetic STORE zip** (not a game dump) and checks
alignment, path sanitizing, and shutdown lifetime.

## What M9 forbids

- Committing or uploading `.o2r` / ROM data.
- Desktop StormLib / libultraship archive code on ARM11.
- Claiming title-screen assets are loaded (M12).
