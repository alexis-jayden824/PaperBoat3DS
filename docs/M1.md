# M1 — Reproducible Build & CI

**Goal:** a clean checkout produces the expected artifacts under a documented
and pinned environment.

## Pins

| Input | Pin |
|---|---|
| Docker image | `devkitpro/devkitarm@sha256:15b79ce75822c289538d8153da5fa7aafe5e6adc32ad8a575a197beca0f0761b` |
| makerom | Project_CTR `e8f5f529c54ff9b22a2491a480ffa69206bf7b19` |
| Host packages | `3ds-dev` |
| CPU | ARMv6K mpcore hard-float |

The lock file is `toolchain/TOOLCHAINS.lock`. `tools/check_toolchain_lock.sh`
fails if `.github/workflows/3ds-build.yml` drifts from that file.

## Metadata

Every CI binary is compiled with:

- `PB3DS_BUILD_SHA` = Git commit
- `PB3DS_BUILD_UTC` = UTC timestamp of the job

`tools/write_build_info.sh` writes `build/build-info.txt`, which is uploaded
next to the `.3dsx` and `.3ds`.

ELF/CCI bytes are **not** claimed bitwise-identical across hosts: object
timestamps and path differences remain. Reproducibility here means the same
toolchain pin, same source, and recorded identity of the artifact.
