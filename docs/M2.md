# M2 — Dependency Graph / Portability Audit

**Goal:** map PaperBoat, libultraship, Torch, and 3DS dependencies, classify
portable vs platform-specific code, and freeze the integration boundary
**before** any game source is compiled into the ARM11 application.

This milestone does **not** compile PaperBoat. Fetching and compiling the
pinned game core is M5. The compatibility layer is M6. Graphics backends
are M11+.

## Audited baseline

Pins live in `upstream/PAPERBOAT.lock` and were verified against GitHub on
2026-09-26:

| Tree | Release / role | Commit | License |
|---|---|---|---|
| [HarbourMasters/PaperBoat](https://github.com/HarbourMasters/PaperBoat) | 1.0.1 (Mulberry Bravo), game + port | `424c220f0863c29b9fe55cc674baceff88e9e14f` | CC0-1.0 |
| [JeodC/libultraship](https://github.com/JeodC/libultraship) | PaperBoat engine (submodule) | `7aa03b6c830b059e3ddd6ad20d3f289c5f406161` | MIT |
| [JeodC/Torch-LH](https://github.com/JeodC/Torch-LH) | PC ROM → `.o2r` factory | `106f4e3056f07fe3a8758bb14a060f8423b6877f` | MIT |

PaperBoat 1.0.1 at that commit is the behavioral reference. Do not track
`main`. Do not vendor these trees into git.

## Architecture (frozen for later milestones)

```
+------------------+     C ABI, N64 types      +----------------------+
| PaperBoat game   |  -----------------------> | pb3ds compatibility  |
| (src/*.c, EVT,   |   boot_main / step_game_  | (M3–M6, C, no SDL)   |
|  gfx_draw_frame) |   loop / gfx_draw_frame   |                      |
+------------------+                           +----------+-----------+
                                                          |
                                                          | libctru / citro3d /
                                                          | HID / SDMC / ndsp
                                                          v
                                               +----------------------+
                                               | Nintendo 3DS         |
                                               | Old 3DS baseline     |
                                               +----------------------+

PC only (never linked into ARM11):
  Torch-LH + legal baserom.us.z64 --> paperboat.o2r + pm64.o2r
```

PaperBoat remains the source of truth for gameplay. The 3DS tree supplies
platform services and a graphics API. It must not replace game logic with
approximations or demo geometry.

## Classification

### A. Portable — reuse in M5+ (game/core)

Compile with PaperBoat’s own exclusions, not “every `.c` file”.

| Area | Upstream | Notes |
|---|---|---|
| World, battle, EVT, entities | `src/` minus excluded dirs | Gameplay |
| Headers / N64 types | `include/` | ABI |
| Globals | `src/port/init_globals.c` | Startup |
| libc shims | `src/port/libc_compat.c` | N64-era helpers |
| Frame boundary | `src/port/gfx_frame.c` | Display-list handoff |
| Data bridges | `ld_addr.c`, `decode_yay0.c`, `shape_loader.c`, `effects_shim.c` | Decomp/OTR |
| Entry | `boot_main`, `step_game_loop`, `gfx_draw_frame` | Required symbols |

Desktop PaperBoat already drops `src/port/` engine, `src/os/`, `src/boot/`,
effect DLs replaced by OTR, and non-US region units. The 3DS selector must
keep those exclusions.

### B. Compatibility surface — implement in M6 (minimum libultraship)

Do **not** link the desktop libultraship tree. Reimplement the contracts the
game actually calls:

| Contract | Game expectation | 3DS owner |
|---|---|---|
| Resources | OTR/O2R name and CRC lookup | M9 SDMC/RomFS reader |
| Logging | Engine log sink | M4 |
| Config | Key/value, no GUI | M15 / bottom menu M16 |
| Controller | `OSContPad` | M8 HID |
| Time | Tick / frame hold | M10 |
| Gfx API | Fast3D `GfxRenderingAPI` behavior | M11–M13 PICA translator |
| Audio hooks | Mixer submit | M14 ndsp (until then: explicit no-op) |

Anything else in libultraship is out of the initial subset: SDL window,
ImGui, Fast3D OpenGL/Vulkan/Metal, desktop audio devices, Windows/Android
paths, updaters, web, DLL/TCC mod loaders, `std::filesystem`, extra threads
for the game loop.

### C. Desktop-only — isolate or delete from the 3DS path

| Path / system | Why it cannot ship on 3DS |
|---|---|
| `src/port/Game.cpp`, `Engine.cpp` | SDL2, ImGui, desktop Fast3D, filesystem, threads |
| libultraship window/controller/audio backends | Desktop devices |
| Native file dialogs, crash dialogs | No Win32/Cocoa/GTK |
| Torch, StormLib extractors, YAML factories | Host-only legal pipeline (M7) |
| Mod loaders / updaters | Unbounded memory and I/O |
| C++20-heavy engine facilities | ARM11 budget and toolchain |

`src/port/nusys_overrides.c` documents the NuSystem/libultra surface but
delegates to the desktop engine. M6 must give those symbols 3DS semantics,
not copy the desktop bodies.

### D. 3DS platform — this repository

| Service | Library | Milestone |
|---|---|---|
| Lifecycle / APT | libctru | M0 (done) |
| Toolchain / CI | devkitARM (pinned) | M1 (done) |
| Platform C API | `include/pb3ds/` | M3 |
| Memory / logs | linear/heap, SDMC log | M4 |
| Input | HID | M8 |
| Files | SDMC `sdmc:/3ds/PaperBoat3DS/` | M9 |
| Timing / loop | APT + `osGetTime` | M10 |
| GPU | citro3d / PICA200 | M11–M13 |
| Audio | ndsp | M14 |
| Menu | bottom 320×240 | M16 |

Old 3DS is the memory/CPU baseline. New 3DS extras stay opt-in.

### E. PC asset pipeline — Torch stays off-device

Torch-LH at `106f4e3056f07fe3a8758bb14a060f8423b6877f` plus PaperBoat
`assets/yaml/us/` produces `paperboat.o2r` and `pm64.o2r` from a legally
obtained `baserom.us.z64`. Extraction never runs on the 3DS. Archives are
never committed. M7 owns the wrapper and hash checks.

## Known ARM11 constraints (do not ignore in M5)

- The desktop engine assumes a large heap, C++20, threads, and dynamic
  loading.
- Fast3D is coupled to GL-style clip/Y/depth; the 3DS path must preserve
  PaperBoat’s **command interpretation** and only swap the final GPU API.
- Thousands of translation units need a generated source list and
  `--gc-sections`, not a hand-maintained dump of the whole tree.
- O2R indexing must be measured on Old 3DS before copying a desktop cache.
- Crash/stack paths using desktop APIs must be replaced (M4).

## What M2 forbids

- Compiling PaperBoat into this `.3dsx` yet (M5).
- Linking desktop libultraship or SDL.
- Scene-specific renderer hacks or fake Toad Town geometry.
- Committing ROMs, `.o2r` files, or Nintendo assets.

## Handoff

1. **M3** — C platform headers: gfx, input, fs, time, memory, log, lifecycle.
2. **M5** — fetch pins into `.cache/upstream` (gitignored), compile a small
   core slice with PaperBoat’s exclusions.
3. **M6** — smallest C compatibility surface; unsupported calls fail
   explicitly.
4. **M7** — host Torch wrapper.
5. **M11+** — PICA Fast3D-equivalent interpreter, not a second game.

M2 is complete when this pin and classification are committed and the host
lock test passes. It does not claim the game core compiles.
