# M7 — Legal Asset Pipeline

**Goal:** prepare `paperboat.o2r` and `pm64.o2r` on a **PC**, from a dump the
owner obtained legally. Never commit Nintendo ROM data. Never run Torch on
the 3DS.

## Identity

PaperBoat 1.0.1 `config.yml` keys the US retail image by SHA-1:

`3837f44cda784b466c9a2d99df70d77c322b97a0`

That value is copied to `upstream/ASSETS.lock` and
`include/pb3ds/assets.h`. The wrapper refuses any other file. This repository
does not contain the ROM and will not fetch one.

| Archive | Producer | Ships in git? |
|---|---|---|
| `pm64.o2r` | Torch-LH `./torch otr baserom.us.z64` plus `assets/yaml/us` | no |
| `paperboat.o2r` | Desktop PaperBoat `GeneratePortO2R` from `port/` | no |

Copy both onto SD (`sdmc:/3ds/PaperBoat3DS/`). Extraction is M7; reading
archives is M9.

## Host wrapper

```sh
sh tools/fetch_torch.sh
sh tools/prepare_assets.sh --dry-run
sh tools/prepare_assets.sh /path/to/baserom.us.z64
```

`--dry-run` fetches pinned Torch-LH (`106f4e3056f07fe3a8758bb14a060f8423b6877f`)
into `.cache/upstream/Torch-LH`. A real ROM is SHA-1 checked, then Torch runs
only if `TORCH_BIN` (or a local Torch build) exists. Manifests land in
`.cache/assets/` (gitignored).

ARM11 `pb_assets_extraction_on_device()` is always false. `make` does not
compile Torch.

## Host contract

```sh
sh tools/test_m7.sh
```

## What M7 forbids

- Committing `.z64`, `.n64`, `.o2r`, or other game assets.
- Uploading those files from CI.
- Linking Torch into the `.3dsx`.
- Instructing anyone to obtain a ROM they do not own.

M7 is complete when the host contract passes and CI still produces `.3dsx`,
`.3ds`, and `.cia` without asset archives.
