# M5 — PaperBoat Source Integration

**Goal:** put the pinned PaperBoat 1.0.1 tree in the 3DS build graph and
compile a **small core slice** with PaperBoat’s own exclusions. Do not run
the game. Do not link desktop libultraship, SDL, or Torch.

## Fetch

```sh
make fetch
# or
sh tools/fetch_paperboat.sh
```

Pins come from `upstream/PAPERBOAT.lock`. The tree lands in gitignored
`.cache/upstream/PaperBoat` at `424c220f0863c29b9fe55cc674baceff88e9e14f`.
libultraship is M6. Torch stays host-only (M7).

## Slice actually compiled into ARM11

| Upstream file | Why it is in M5 |
|---|---|
| `src/port/libc_compat.c` | N64 `_Printf` shim, no engine |
| `src/port/decode_yay0.c` | Portable decompressor, no SDL |

Wrappers: `source/pb_upstream_libc_compat.c`, `source/pb_upstream_yay0.c`.
`decode_yay0.c` includes `ultra64.h`; M5 supplies integer types only in
`include/pb3ds/n64shim/ultra64.h` so we do not pull libultraship headers.

`source/paperboat.c` exposes `pb_paperboat_*` and probes the slice at boot.
`boot_main` / `step_game_loop` / `gfx_draw_frame` are **not** compiled.

## Exclusions (frozen from PaperBoat CMake)

`upstream/PAPERBOAT.exclusions` must match `CMakeLists.txt` FILTER rules:
drop `src/port/` (except this explicit slice), `src/os/`, `src/boot/`,
effect GFX blobs, non-US units, and the other CMake exceptions.

M5 does **not** compile the rest of `src/*.c`. Thousands of units wait for
a generated list plus `--gc-sections` once M6 exists.

## What is still not PaperBoat

The `.3dsx` remains a shell. Linking two portable C files does not boot
Paper Mario. No fake overworld.

## Host contract

```sh
sh tools/test_m5.sh
```

Fetch, match exclusions to CMake, refuse Torch/LUS clone, compile the
slice, run `_Printf` and Yay0 tests.

## What M5 forbids

- Linking `Game.cpp` / `Engine.cpp` / SDL / desktop Fast3D.
- Fetching Torch or libultraship into the ARM build.
- Claiming `boot_main` runs.
- Vendoring upstream trees into git.

M5 is complete when the host contract passes and CI fetches the pin, links
the slice, and still produces `.3dsx` / `.3ds`.
